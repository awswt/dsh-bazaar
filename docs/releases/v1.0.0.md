# v1.0.0

- 发布版本：`v1.0.0`
- 上一个版本：无（本仓从 1.0.0 起算，0.x 历史不在本仓重述）
- 提交说明：单上游插件升级为多 provider 集市——provider 注册表 + 五域编排 + 两个前端屏，上游事实全部下沉到 `providers/<providerId>`
- 测试：384 条通过（39 个测试文件）
- 安装：`dsh plugin --profile <profile> add git+https://github.com/awswt/dsh-bazaar.git`；**本版不做 npm publish**

## 本次新增与修复

### 用户可见

- **设置页改成按 provider 分页签**：页签集合由注册表驱动（一家库一个页签，标题取 `displayName`），每页签固定四块——账号 / 凭据 / 缓存 / 连接器授权。注册表为空时整块给空态；单个库加载失败只红该页签内容，页签条照常可切换，切页签不会连带刷新别家的加载状态。
- **账号区要求先选登录区域**：「国内版 / 国际版」下拉为必填且**不预选**，未选就点登录只在原地报字段级错误（`aria-invalid` + 锚定说明）、不发请求；绕过界面直接提交时服务端以 `BAZAAR_PARAM_INVALID` 拒绝并点名 `region`。凭据未配置时登录按钮禁用并写明原因（`BAZAAR_AUTH_MISSING`）。
- **凭据值只读**：只显示「凭证名 / 是否已配置 / 脱敏值」，脱敏容器是 `role="textbox" aria-readonly="true"`，没有编辑入口；明文密钥出现在配置里会被 `BAZAAR_AUTH_INLINE` 拦下。
- **危险操作要二次确认并写明范围**：清理缓存、退出账号、清除连接器授权都先弹确认，确认文案点名对象与影响（例如清除授权＝「移除该连接器的授权记录并使其工具不可用」），取消不改任何状态。
- **会话面板改成多选开关 + 分组卡片**：开关组标题「选择专家库（可多选）」并标注「可选」——**全不勾选是合法空态**，显示「尚未选择专家库」与入口，不阻断浏览与搜索；每个开关带「已启用 / 未启用」文字标签。
- **专家条目四态可辨**：`当前使用` / `应用中` / `已选` / `禁用：未选择该专家库`，全部是文字标签而不是只有颜色；跨库同名只在重名时加 `<displayName> ·` 前缀，不改真实 id。
- **技能区按库并列两列来源**：`skillMarket` 与 `memoryMarket`。跨库同名冲突给「冲突」标签 + 禁用安装 +「禁用：已被 X 安装」+「查看已有安装」；未声明 `memoryMarket` 的库其记忆搜索框禁用并写「禁用：未声明 memoryMarket」，不以「暂无条目」冒充空态。
- **单库故障隔离**：任一库的取数失败只让它的分区报错并给「重试」，重试只重发失败那一家；其他库的条目与状态不受影响。

### 模型工具与命令

- **`bazaar_helper`** 取代旧工具名，新增 `provider` 参数与 `providers` 列举动作；`experts` / `skill-market` / `connector` / `account` 都接受 `provider=<id>`。不传 `provider` 时按会话活跃集解析，活跃集为空或有多个库时返回 `BAZAAR_PROVIDER_REQUIRED`（提示里给出可用的 `provider` 值），不再静默取第一家。
- **`/bazaar`** 取代旧命令名，支持 `status | providers | experts [provider=<id>] [query] | expert <id> provider=<id> | off | skills [install <skillId> provider=<id> [--force] | installed] | connector <...> [id] | account <...> [id] [region=cn|global] [loginId=<id>] | market <query>`；`provider=` / `categoryId=` 可出现在任意位置。

### 契约与实现

- **新增 provider 契约与注册表**：provider 以 `apiVersion: 1` 注册，用 `capabilities` 声明五域（`expertMarket` / `skillMarket` / `memoryMarket` / `connectorMarket` / `account`）；注册点为 `ctx.bazaar.providers.register/unregister/list/get`。未声明的域一律 `BAZAAR_CAPABILITY_UNDECLARED`，界面渲染「未声明 · 不适用」而不是空态。
- **五域下沉为内置 provider**：仓库只内置 `workbuddy`，承载专家双源、技能市场（含委托记忆插件的记忆市场）、连接器市场与账号登录；`marketMode` 与全部上游端点降为该 provider 的内部细节。
- **数据布局按 provider 分区**：`<DSH_HOME>/bazaar/providers/<providerId>/{accounts,vault,cache}/` 与 `connectors.json`；会话状态按会话分文件、按 providerId 分组原子写入，切换专家库不再覆盖另一家的选择。
- **HTTP 路由**：前缀 `/dsh-bazaar/*`；按 provider 取数新增 `/providers/<providerId>` 分组段（`status` / `accounts` / `accounts/action` / `connectors` / `connectors/session` / `connectors/action` / `skill-install` / `cache/clear`），另新增 `GET /providers`（列举）与 `POST /providers/active`（活跃集写入，接受空数组）。陈旧路由自愈只清自己前缀的条目。
- **连接器动作集收敛**：`list` / `state` / `authorize` / `poll` / `cancel` / `copy-config` / `remove`；写入宿主配置并重载留待 1.1.0，「复制配置片段」只产出文本。
- **出网校验下沉**：`allowHosts` 与 `allowInsecureLoopback` 从插件级下沉到 `providers.<id>`，四个出网入口（在线市场 / 公开快照 / 登录 / 连接器刷新）与技能包下载统一经 `assertAllowedUrl`，逐 provider 独立。
- **彻底移除 dsh-armory 复用**：两处 `remote.mcpManager` 取值与全部降级分支删除，不保留回退。

### 工程

- 质量门（`npm run check`）覆盖 EOL、逐文件 `node --check`、用例数下限、ESLint（含压制清单与压制增量判定）、Prettier 与「基线文件未被改动」；`.prettierignore` 改为受管文件登记表（只写精确路径与目录，不用通配），新文件必须登记进受管集合。
- 四份静态扫描用例带反向控制：钩子顺序守卫、设置页两个 id 同源、旧前缀路由清理、目录/文件清单一致性。
- 新增两屏离线回放 `node scripts/e2e.mjs --plan ui`：不装包、不起模型、不出网，用本地假服务跑通屏 A / 屏 B 的全部状态语义。

## 升级说明

1. **包名与安装源变了**：`dsh-bazaar`；旧包名不再发布。安装后确认 profile 的 `dsh.profile.bundles` 含 `dsh-bazaar`（`cordis.patch.yml` 会带入插件层）。
2. **凭据要重建**：凭据名由 `providerId` 推导为 `BAZAAR_<UPPER_SNAKE(providerId)>_TOKEN`（内置库即 `BAZAAR_WORKBUDDY_TOKEN`）。旧凭据名不再读取，请在宿主凭据服务里按新名写入，或用 `providers.<id>.credentialRef` 指回你自己的名字。
3. **配置要改写**：插件级只剩 `enabled` / `defaultProvider` / `dataDir`；其余键（`authMode`、`headerName`、`headerPrefix`、`allowHosts`、`allowInsecureLoopback`、`marketMode` 等）要么下沉到 `providers.<id>`，要么按下方移除清单删除。`authMode` 的 `auto` 与 `workbuddy-connector` 两个取值已删除，改用 `none`（默认，匿名只读公开快照）/ `bearer` / `header` / `cookie`。
4. **要重新登录、重新选择、重新授权**：本版**不迁移旧数据**——不探测、不提示、不读取 1.0.0 之前的数据目录与兼容层 vault 目录。升级后账号需重新登录，会话需重新勾选专家库，连接器需重新授权。
5. **旧目录可整体删除**：`<DSH_HOME>/bazaar` 下的内容全部可再生（账号需重新登录、市场缓存自动重建、会话状态重建为空态）；回滚到旧版本前先备份该目录即可。
6. **接口调用方要改**：错误码前缀统一为 `BAZAAR_*`（`BAZAAR_CONNECTOR_MISSING` 与 `BAZAAR_CONNECTOR_NO_TOKEN` 删除，语义由 `BAZAAR_AUTH_MISSING` / `BAZAAR_CONNECTOR_NOT_FOUND` 承接）；设置项 id 为 `bazaar-account`、会话面板入口 id 为 `bazaar-expert-picker`（`order` 仍为 25 / 26）；CSS 类名前缀 `bz-`；exports 的八个旧 subpath（`./wb-login`、`./wb-vault`、`./wb-accounts`、`./connector-flow`、`./skill-providers`、`./market`、`./portal`、`./connector`）合并为 `./provider` 与 `./providers/workbuddy`。
7. **不发布 npm**：`publishConfig` 字段保留，但本版物料只推 GitHub；安装走 `dsh plugin ... add`。

完整的破坏性变更与移除清单见 [`CHANGELOG.md`](../../CHANGELOG.md)；模块分层见 [`docs/architecture.md`](../architecture.md)；e2e 基线与用例矩阵见 [`docs/e2e-baseline.md`](../e2e-baseline.md)。

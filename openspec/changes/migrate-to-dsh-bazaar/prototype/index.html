原型范围 Prototype Scope

本原型只回答两屏的布局、分组形态与状态语义，不回答数据来源与内部实现。

  • 在范围内：设置页的 provider 分页签结构（账号 / 凭据 / 缓存 / 连接器授权四块）、默认专家库空态、单页签加载与出错；会话辅助面板的 provider 多选开关、按库分组并列、搜索与分类筛选、技能市场与记忆市场两个来源、单库故障隔离、跨库同名前缀、空态与危险操作确认。
  • 不在范围内：真实接口与网络行为、真实扫码登录、真实落盘路径、权限与凭据解析细节、provider 注册表本身（属 spec 而非界面）。
  • 示意数据：内置 WorkBuddy（对应 providerId=workbuddy）、示例专家库（demo，示意第三方 provider）、Beta 专家库（beta，用于演示出错与未启用两种状态）。三者都是占位数据，不含任何真实账号或密钥。
  • 不涉及：连接器「一键写入宿主配置并重载」——该能力留待 1.1.0，本原型不出现对应入口。

屏 A · 设置页 — DSH 设置 › 扩展 › dsh-bazaar 静态示意 + 局部可点

专家库设置

默认专家库：未选择 空数据

defaultProvider 为空。新会话的 activeProviders 是空数组，会话面板显示「尚未选择专家库」， 模型工具未传 provider 时返回 BAZAAR_PROVIDER_REQUIRED 引导错误——不会静默回落到第一个已注册的专家库。 配置指向未注册 id 时会报错并回落首个已注册。

本屏回答的需求：provider-registry「设置页与面板的 provider 区域由注册表驱动并标注状态」、 account-auth「账号区界面状态语义」、connector-market「连接器界面状态语义」、「复制配置片段只产出文本」。 为什么这样设计：一个 provider 一个页签，页签标题取 displayName（不显示 providerId）， 因此新增 provider 不需要改界面代码；出错时只把该页签的内容区标红，页签本身仍可切换，避免一个上游故障让整页不可用； 凭据只出现「名称 + 是否已配置 + 脱敏值」，值永不可编辑，从界面上排除密钥被误改的可能。

屏 B · 会话辅助面板 — 对话输入区左侧「集市」 多选开关可点

集市 · 会话辅助

会话 sess-demo · 状态来自会话状态文件，非全局

选择专家库（可多选） 可选 可同时勾选多个；每个勾选项在下方向自己的分区取数

本开关组不是必填项：全不勾选是合法空态，下方显示「尚未选择专家库」入口，不因此阻止浏览或搜索。真正的必填在请求层——单次选择 / 安装请求缺少 providerId 才返回 BAZAAR_PROVIDER_REQUIRED。

专家 按专家库分组并列；同一条目名出现在多个库时带「库名 ·」限定前缀

技能 每个专家库两个来源：技能市场 / 记忆市场，分别取数、分别报错

本屏回答的需求：expert-market「专家列表按 provider 分组并列返回」「未选择任何专家库时显示空态并给出入口」 「单个 provider 故障隔离」「跨库同名专家以 provider 限定前缀区分」「专家列表与选择的界面状态语义」； skill-market「技能市场按 provider 分组并标注来源」「跨库同名技能安装必须被拒绝并指出已有来源」「记忆市场在宿主缺少记忆插件时显式不可用」「技能区的界面状态语义」； connector-market「会话级工具门控按 providerId 分组 deny 并合并」（未启用库的条目以禁用态呈现）。 为什么这样设计：顶部用多选开关而不是单选下拉，因为一个会话可以同时用两个专家库； 每个库一个独立分区、独立请求、独立错误与重试，使「一个库挂了」不会伪装成「整个集市挂了」； 同名条目加限定前缀但不改真实 id，选择时仍按 providerId + id 双键提交，避免前缀污染身份。

设计系统对齐 Design System Alignment

设计基准文件：DESIGN.md（仓库根目录，与 AGENTS.md 同层， @google/design.md lint 结果 errors 0 / warnings 0）。本原型的全部颜色、字号、圆角与间距取值都来自该文件， 不在本文件内自造视觉语言。

  • 取色基准：DESIGN.md 的 colors 键。实际落地时优先读宿主 --dsw-alias-* / --dsw-static-neutral-bluish-* 令牌（源插件 CSS 即以此为基础），原型独立打开时用 --bz-* 承接同一组值并带宿主令牌兜底，语义与宿主一一对应：背景 / 表面 / 次级表面 / 边框 / 主色 / 成功 / 警告 / 危险。
  • 状态色对比度：三组状态色取同色系最深档配最浅底（error #570C0C on #FEF2F2 = 13.12:1、success #233C2C on #E6FAED = 10.98:1、warning #27241F on #FEF5E7 = 14.30:1），而非宿主的 state-*-primary（在浅底上仅 2.15–4.50:1，不达 WCAG AA）。state-*-primary 只用于边框、圆点等非文字承载。
  • 类名前缀：统一 bz-，与变更约定的 CSS 前缀一致，避免与宿主样式冲突。
  • 字号：只用 DESIGN.md 登记的 16 / 14 / 13 / 12 / 11 px 五档；层级靠字号与字重，不靠更浅的灰。
  • 圆角与投影：圆角只用 rounded 刻度的 5 / 8 / 12 / 999px；不使用投影表达层级（宿主 --dsw-mask-blur 为 none），层级由底色与 1px 边框承担，浮层用 bg-mask-1 遮罩分离。
  • 深色模式：[data-theme="dark"] 覆盖整组令牌并反转前景/背景，所有徽标保留边框与文字（不靠纯色块表达状态），因此在两种主题下都可辨。
  • 状态语义来源：必填 / 禁用 / 只读 / 空 / 加载 / 出错 / 危险操作七类，与 specs/ 中「界面状态语义」需求逐条对应，并已写入 DESIGN.md 的 Components 状态清单（含程序承载 aria-* 与属性名）。
  • 版式：设置页卡片最大宽度 820px，DESIGN.md 规定内容区上限 1120px，本屏取更窄的列宽；面板分组用自适应网格，窄屏自动堆叠为单列。
